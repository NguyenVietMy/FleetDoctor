# Filesystem samples and freshness

The host agent uses `os.statvfs` for each configured absolute path, default `/`. These fields are Linux `statvfs` counters, not a `/proc` text parser. Fixture data in `tests/fixtures/statvfs.json` is explicitly synthetic and includes reserved blocks, zero capacity and malformed counters. Kernel OOM/process/network collectors are later slices.

| Sample field | Meaning and unit |
| --- | --- |
| `total_bytes` | `f_blocks * f_frsize`, bytes |
| `free_bytes` | `f_bfree * f_frsize`, including reserved blocks, bytes |
| `available_bytes` | `f_bavail * f_frsize`, available to the unprivileged workload, bytes |
| `used_bytes` | `(f_blocks - f_bfree) * f_frsize`, bytes |
| `block_usage_percent` | `100 * used / (used + available)`; accounts for reserves like `df`, percent |
| `inodes_total`, `inodes_free` | `f_files`, `f_ffree`, counts |
| `inode_usage_percent` | `100 * (total - free) / total`, percent |

Zero denominators, invalid counters, unreadable paths and collection deadlines produce null values with a source-specific error. Bad inode counters preserve valid block data; a bad path preserves healthy sibling paths when the worker can proceed. Prometheus ratio metrics divide sample percentages by 100. Prometheus families encode bytes, inode counts or ratios separately; only bounded node and configured filesystem labels are used.

Schema v1 retains its exact historical filesystem JSON and fingerprint shape. Schema v2 adds a required CPU envelope and exact CPU units. Schema v3 requires the unchanged CPU envelope plus memory units and a memory envelope. Schema v4 keeps those envelopes and adds bounded FD observations; deploy the compatible collector before newer agents. Every sample includes node ID, boot UUID, new agent-session UUID, increasing sequence and a timezone-aware observation time. A registered node's bearer token must match its node ID. Tokens are compared in constant time and never echoed in payload errors. This is a private-network lab transport, using HTTP within a restricted VPC; tokens are not protection against an attacker with access to that network or a host's credential. Interface access uses SSH tunnels, and Uvicorn ignores proxy headers.

## File-descriptor semantics

The FD collector forms a bounded union of up to 16 configured PIDs, top CPU/RSS identities, and 32 active watches, with at most 68 results and a 24 KiB FD envelope. Each identity is boot UUID, PID, and `/proc/PID/stat` start-time ticks. Direct reads bracket the identity, parse the process's current finite positive `Max open files` soft limit, and count numeric `/proc/PID/fd` entries without resolving targets. Unlimited, zero, malformed, missing, denied, raced, zombie, and replaced states are explicit; missing from a partial/top inventory is not exit evidence.

Pressure is `descriptor_count / current_soft_limit` and is not clamped. Growth evidence carries the signed integer descriptor delta, agent monotonic interval, and derived descriptors/second together for the same identity when the interval is in `(0,10]` seconds. First/restarted/reset/replaced/long-gap baselines and count failures make all three fields null. Positive growth supports suspected leakage but is not a trigger requirement or causal proof.

Three eligible readings at or above the configured 90% open threshold create an exact-identity warning. Three readings strictly below the frozen 80% recovery threshold resolve by release. Three direct exact-exit/replacement observations or three stable new-boot confirmations have separate reasons. Active identities are returned through the authenticated node watch response so they remain directly probed when they leave top lists. Watch refresh has a one-second outer elapsed deadline; failures retain the previous valid cache and a valid empty response clears it.

Prometheus exports bounded node aggregates only: `fleetdoctor_fd_pressure_ratio`, `fleetdoctor_fd_count`, `fleetdoctor_fd_soft_limit`, `fleetdoctor_fd_growth_per_second`, `fleetdoctor_fd_coverage_ratio`, admission availability, and current candidate-overflow rejection. PID, command, boot and start time are not metric labels. A missing current maximum is absent rather than a healthy zero; read freshness and coverage with range history. Exact identity, count, actual limit, signed count delta/rate/interval, source errors, lifecycle reason, and investigation steps remain API/SQL incident evidence.

## Inode diagnosis semantics

Inode diagnosis coverage requires fresh inode totals/free counts, inode use, block use, and a present available-bytes counter for the configured filesystem; zero available bytes is measured data, not missing coverage. Three eligible observations at or above 95% inode use open `inode_exhaustion` only while available bytes are positive and block use remains below the effective block guard. The effective guard is `min(inode block guard, disk trigger)`, so lowering the disk trigger cannot make disk and inode rules open from the same sample; a separately configured inode guard is retained only when stricter. The effective configuration is frozen in the incident.

Recovery is inode-specific: three fresh observations below 90% inode use resolve an active inode incident even when block counters are unavailable. `inode_available` and `block_available` remain separate evidence flags, and the Grafana incident lifecycle selects the former for inode incidents. Missing inode evidence never becomes healthy zero data.

## Memory and OOM semantics

`/proc/meminfo` supplies `MemTotal`, `MemAvailable`, `SwapTotal`, and `SwapFree` in KiB, converted to bytes. Zero swap capacity is valid. `/proc/vmstat` supplies raw `pgfault`, `pgmajfault`, `pswpin`, and `pswpout` counters. Rates require a positive monotonic interval no longer than ten seconds and nondecreasing counters; swap pages are multiplied by the runtime page size before division. A first observation, worker restart, counter decrease, or long gap leaves rates unavailable.

Each configured canonical non-root cgroup path is read with no-follow bounded files. Generation identity is boot UUID plus directory device/inode. The collector brackets usage/limit reads with two `memory.events.local` reads and rechecks the directory identity. A changed bracket makes usage/recovery ineligible, but the final defensible local counter can still show a new kill. `memory.max` and `memory.swap.max` preserve `max` as explicit unlimited state, separate from missing. `memory.current / memory.max` is not clamped and may legally exceed 1.0. Missing workloads are omitted, never zero-filled. At most ten PID/start-time/RSS rows per workload remain API evidence.

The workload rule compares current local counters with the durably checkpointed previous sample for the same generation. `oom_kill` deltas open immediately; `oom` without a kill cannot open. Recovery requires three stable fresh ratios below 0.80 and zero new `oom`/`oom_kill` deltas. Cumulative nonzero counters are not a latch. Kernel journal evidence is current-boot, incremental, output/record/text bounded, and baselined without replay; permission, cursor, boot, and truncation failures reset that baseline explicitly. The collector requests 65 records to make its accepted 64-record cap observable; overflow discards the interval and rebaselines. Retained messages are bounded by UTF-8 bytes to 512 bytes each and 8KiB total. Missing permissions do not suppress local-counter evidence. Only an explicit exact `oom_memcg=`/`memcg=` path in the same bounded log event is treated as scoped corroboration. Configured leaves that cannot be collected appear under bounded `memory.workload_errors`; their data gauges remain unavailable while `fleetdoctor_memory_coverage_ratio` emits zero for that configured scope on every scrape.

The collector accepts an observation only at age **[-2,10] seconds**. Duplicates, superseded sequences, retired sessions and non-increasing observation times cannot replace current data. Late/future samples cannot refresh node age; the API exposes delivery errors separately. Resource gauges and API `filesystems` become unavailable at age >10s; stale status is true at age >15s. Before a first observation, age is null and stale is true. When freshness expires, the API retains sample identity and timestamps but removes filesystem values and clears available-field coverage. A collector restart reloads bounded ordering and age metadata, but restored samples are deliberately non-live: resource/delivery gauges remain absent and rule windows start empty until new eligible commits arrive.

Prometheus scrapes every five seconds. When gauges disappear, history reflects the live delivery gap; range evaluation can repeat the last scraped gauge within Prometheus's lookback, so freshness must be assessed using age/coverage, not an interpolated graph. Grafana uses ordinary missing-point display and does not substitute zero for missing resource metrics. Coverage is the available field fraction, set to zero when the sample is no longer fresh. Collection errors remain available through the API.

The CPU worker reads the first eight aggregate `/proc/stat` counters: user, nice, system, idle, iowait, irq, softirq, and steal. Guest fields are not added because Linux already includes them in user/nice. Executed busy percent is `(user+nice+system+irq+softirq delta) / total delta`; iowait and steal use the same denominator but remain separate. The first interval, counter decrease, zero delta, online-core-set change, or monotonic interval outside `(0,10]` seconds resets rates to unavailable. `/proc/loadavg` 1/5/15 values are context and are not interchangeable with instantaneous `procs_running`.

Process CPU is `(utime+stime tick delta) / CLK_TCK / elapsed * 100`; 100 means one logical core, so a multithreaded process may exceed 100. Identity is PID plus `/proc/PID/stat` start-time ticks and the sample boot ID. The collector reads at most 4096 process entries, at most 4096 bytes per source, with a 0.5-second scan budget; it returns bounded top CPU/RSS rows plus up to 16 configured PIDs. Partial/permission-limited coverage is explicit. Full command lines and environments are never collected.

The agent schedules with a monotonic clock every five seconds. A missed tick skips catch-up bursts. Upload has a total two-second deadline including the response body, and response size is capped at 16KiB. Filesystem collection has a one-second budget; CPU and memory collection each have a 0.75-second budget, and FD collection has a 0.75-second worker budget, in separate long-lived spawned children. Child startup uses readiness handshakes outside those budgets. Termination/join is bounded, and no replacement worker is launched while an unkillable worker remains alive. CPU and RSS of all children **count toward** task 16 overhead measurement; no overhead result is claimed here. Failed uploads are logged by error class only and the next current sample is sent.
